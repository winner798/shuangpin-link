# 双拼互联后期调试说明

## 从源码生成安装包

Windows 使用 Python 3.10+、Git、PowerShell 7、.NET 8 SDK、7-Zip，以及 Visual Studio 2022 的 C++ 桌面开发工具、ATL、MFC 和 Windows SDK。在仓库根目录运行以下命令。

```powershell
pwsh -NoProfile -File scripts/package-windows.ps1
```

生成 `dist/windows/ShuangpinLinkSetup.exe`。构建时会用 `--check` 检查内置的输入组件和词库文件。手动安装更新前，从托盘退出正在运行的双拼互联。Windows 系统输入组件注册在 `%ProgramFiles%\ShuangpinLink\IME`，个人词库及配置在 `%APPDATA%\ShuangpinLink\Rime`。安装覆盖前的配置副本位于 `%LOCALAPPDATA%\ShuangpinLink\configuration-backup`。

从 0.3.0 或更早的 Windows 版升级时，安装程序会查找旧版安装和词库。识别到旧版安装时，会尝试迁移个人词库和暂停学习状态，并从当前 Windows 用户的输入法列表隐藏之前随项目使用的旧入口。旧输入法的程序文件和原词库会保留。

Android 使用 Python 3.10+、Git、JDK 25，以及 SDK `platforms;android-37.0` 和 `build-tools;37.0.0`。准备完成后用 Gradle Wrapper 构建。`BUILD_ABI` 默认为同文的上游设置，构建本项目时设为 `arm64-v8a,x86_64`。

```sh
python -B scripts/prepare.py android
cd .build/trime
BUILD_ABI=arm64-v8a,x86_64 ./gradlew --no-daemon :app:assembleRelease
```

Windows 上请把仓库检出到纯英文路径，使用 `gradlew.bat`，并通过 `$env:BUILD_ABI` 设置架构。Android Gradle 插件会拒绝当前 `输入法` 这类含中文的构建路径。输出位于 `.build/trime/app/build/outputs/apk/release/`。GitHub Actions 提供同样的未签名构建。使用 `scripts/sign-android.ps1` 和保存在仓库之外的专用密钥完成对齐、签名及校验。APK 升级需延用相同包名和签名证书。Android 手机通常使用 `arm64-v8a`，`x86_64` 用于相应设备或模拟器。

```powershell
pwsh -NoProfile -File scripts/sign-android.ps1 `
  -UnsignedApk path-to-unsigned.apk -OutputApk dist/android/ShuangpinLink-arm64.apk `
  -BuildTools path-to-android-sdk/build-tools/37.0.0 -Keystore path-to-private-keystore.p12
```

签名前，将密钥库密码放入当前终端的 `SHUANGPIN_SIGNING_PASSWORD` 环境变量。备份密钥库并保存密码，以后用同一个证书发布更新。

## 发布两端更新

1. 在 `updates/version.json` 提高 `versionCode` 并填写新的 `versionName`。两端以 `versionCode` 判断是否有更新。重新构建 Windows 安装包和两种 APK，继续用已有 Android 证书签名。
2. 本机用更新签名密钥生成发布目录。发布脚本使用 Python、PowerShell、OpenSSL 和 Android 构建工具检查安装包版本。`.local/update-signing-key.pem` 要与 `updates/public-key.spki.b64` 对应。后续发布应保管并沿用同一密钥。

```powershell
python -B scripts/release-update.py stage `
  --key .local/update-signing-key.pem `
  --windows dist/windows/ShuangpinLinkSetup.exe `
  --arm64 dist/android/ShuangpinLink-Android-arm64-v8a.apk `
  --x86-64 dist/android/ShuangpinLink-Android-x86_64.apk `
  --aapt path-to-android-sdk/build-tools/37.0.0/aapt.exe `
  --output .build/update-release
```

3. 从和公开仓库 `main` 一致的干净检出目录运行发布脚本。它会使用 Windows 已保存的 GitHub 登录，也可从当前终端的 `SHUANGPIN_GITHUB_TOKEN` 读取发布令牌。更新签名密钥和 Android 密钥留在本机。

```powershell
pwsh -NoProfile -File scripts/publish-github-release.ps1 `
  -ReleaseDirectory .build/update-release `
  -Notes '填写本次更新说明'
```

发布脚本验证签名和三个安装包，上传到 `v版本号` 草稿，逐一核对 GitHub 的文件散列后再公开。两端从 GitHub Releases 的最新版本下载签名清单和对应架构的安装包。上传中断后可用同一个发布目录重跑。已发布版本要修正时，请提高 `versionCode` 后重新构建。

## 服务管理

Ubuntu 端用系统 Python 3 和 SQLite，监听 `127.0.0.1:18765`。Caddy 把 `/ime-sync/` 转发到该端口。通过 HTTPS 的公共健康检查是 `/ime-sync/health`。正常返回 `{"status":"ok","protocol":1}`。

```sh
systemctl status shuangpin-link --no-pager
sudo journalctl -u shuangpin-link -n 40 --no-pager
curl -fsS http://127.0.0.1:18765/health
```

数据库在 `/var/lib/shuangpin-link/relay.sqlite`，包含两台设备的凭据散列、邀请过期时间、密文词库和最近一条密文剪贴板。剪贴板密文发送 10 分钟后不可接收，服务会在空闲时清理过期记录。已有服务器备份或存储快照由各自的保留策略管理。备份时使用 SQLite 一致性备份，或停止服务后备份。迁移服务器时同时保留 `/etc/shuangpin-link/setup.sha256`，并核对两端服务器地址和 TLS 证书。如果电脑端设备状态丢失，可使用启用码恢复。恢复将解除手机配对并清理旧的远端同步数据。

初始化时生成 32 字节随机启用码，采用不带 `=` 的 Base64 URL 编码。服务器只需要该字符串的 SHA-256 十六进制散列。以 root 身份执行 `scripts/deploy-ubuntu.sh /path/to/server /path/to/Caddyfile example.com /path/to/caddy caddy.service signal`，并从标准输入提供散列。最后一个参数 `signal` 适用于按配置文件启动的 Caddy 2.11+，另可选 `systemd`（已有重载命令）或 `restart`（需在维护时间执行）。脚本在重载前验证配置，健康检查失败时恢复原配置。

## 排查顺序

| 现象 | 检查 |
| --- | --- |
| Android 找不到输入法 | 先安装匹配架构的 APK，在系统设置启用并设为默认键盘，再打开一个普通输入框。 |
| 输入法显示其他拼音方案 | Windows 先按 `Win + 空格` 选择「双拼互联」，然后按 `` Ctrl + ` ``。安卓使用键盘顶部的方案切换入口。菜单应显示微软双拼和普通拼音。 |
| 无法扫码或配对 | 检查手机相机权限、设备时间和 HTTPS 证书。关闭旧二维码后重新生成。若提示已有设备，先在电脑端解除配对。 |
| 剪贴板只能单向同步 | 更新两台设备，确认未暂停互通。用普通测试文字复制并在另一端粘贴。Android 需保持解锁和键盘可用。带系统隐私标记的内容会被跳过。 |
| 两端词频不同步 | 两端开启词库共享，先输入并选中几次同一词，再依次点「立即同步」。确认两端 schema 使用 `rime_ice` 词库。 |
| 清空后旧词条重新出现 | 清空只处理当前设备，并关闭该设备的词库共享。另一台设备的词库仍可用。需要两端从空白开始时，先解除配对，再分别清空本机词库，最后重新配对。Windows 的清空备份在 Rime 用户目录的 `shuangpin-link-cleared` 下。 |
| 发包后 Android 提示签名冲突 | 用上次的签名密钥签名更新。卸载清除本机应用数据前，先导出需要保留的词库。 |
| 检查更新时提示无法验证 | 检查 GitHub 最新 Release 中的 `update-manifest.json` 和三个安装包，核对签名公钥是否与当前客户端内置公钥一致。 |
| 安卓下载后无法安装 | 在系统提示中允许「双拼互联」安装应用，再确认安装。核对安装包架构和应用签名是否与现有版本一致。 |
| Windows 安装后无法切换 | 检查 Windows 语言设置中是否存在「双拼互联」，确认安装时已授权注册系统输入组件。查看双拼互联部署日志，并记录当前 Windows 版本。 |

新版剪贴板使用 HTTPS `/v2/clip`。中继根据配对凭据确定发送方角色，并拒绝未配对的读写。两端通过 HKDF-SHA256 为两个传输方向分别派生密钥，使用 AES-256-GCM 绑定发送角色、消息 ID 和发送时间。接收端验证加密标签，记录最后确认的时间，并拒绝旧消息和重放。旧版剪贴板接口与新版隔离，当前客户端仅使用新版剪贴板通道。个人词库继续使用兼容的 `/v1/dictionary`。调试只使用测试文字，提交日志前去除剪贴板正文、个人词条、启用码和配对信息。

## 回归验证

运行 `python -B -m unittest discover -s tests -v`。协议测试覆盖一次性邀请、设备鉴权、剪贴板长轮询、重复事件、防回传、过期、词库版本与撤销。

每次发布，检查方案菜单只有微软双拼和普通拼音。微软双拼输入 `nihk`、普通拼音输入 `nihao`，都应能选到「你好」。确认断网可打字，中文与英文能切换，续词栏可以关闭。GitHub 的 `Android-keyboard-preview` 构建产物会保留安卓模拟器中的键盘和候选栏截图。`Windows installed input method` 在一次性 Windows 虚拟机里安装实际安装包，通过系统输入服务在独立编辑器中验证两种方案。它会保存 `Windows-installed-input-preview`。

按照 Windows → Android、Android → Windows 顺序测试自动同步。验证启动前的内容不上传、系统标记的内容被拦截、暂停清理待发内容、解除配对后旧设备无法取件，以及两端接收后写入系统剪贴板的隐私标记。Android 的旧版剪贴板历史可在设备互通设置中确认清除。

### 方向键收起续词

在两个字之间留一个插入点，然后用微软双拼或普通拼音输入「你好」并确认上屏。联想栏出现时按一次 `←`，确认正文保持原样、候选消失、光标左移一个位置。在光标右侧有文字时再做一次 `→` 测试。接着输入拼音，确认新的候选正常出现。公共词库和个人学习得到的续词都应满足上述行为。在尚未确认的拼音中另测左右键，确认仍能编辑当前拼音。

### 本机剪贴板历史与连续选词

在一次性测试用户或模拟器中，用没有配对的新安装复制一条长测试文字。Windows 打开托盘历史。Android 在键盘关闭时复制，再打开普通输入框，检查顶栏的省略预览，点「查看」阅读全文并粘贴。删除该条后重新打开键盘，确认它没有重新出现。再复制标记为敏感的测试文字，确认顶栏和历史都没有它。解除配对、删除本机历史和删除系统剪贴板内容是不同的操作。

Android 历史密文位于应用的 `noBackupFilesDir`，密钥由 Android Keystore 管理。Windows 通过当前用户的 DPAPI 加密本机历史。七天的保留期和 50 条上限作用于每台设备；重新打开列表时也会剔除过期项。中继仍只保存限时的最新一条密文。更换系统账户或重装系统时应按新设备建立配对。

用两种方案分别输入首字母组合，并反复选择同一项检验重排。连续确认两个不常相邻的测试词，另起一次输入，确认第一个词后观察第二个词的排名。再换输入框并暂停学习，检查词间联系没有跨越字段。连续选词统计放在 Rime 用户目录的 `link_habits`，两端原有的个人词库同步继续使用 `rime_ice.userdb.txt`。邮箱候选来自随软件提供的域名表。验证 `@g` 补全、普通 `@`、自定义域名和删除操作时可断开网络。
