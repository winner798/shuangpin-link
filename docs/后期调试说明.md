# 双拼互联后期调试说明

## 从源码生成安装包

Windows 使用 Python 3.10+、Git、PowerShell 7、.NET 8 SDK。在仓库根目录运行：

```powershell
pwsh -NoProfile -File scripts/package-windows.ps1
```

生成 `dist/windows/ShuangpinLinkSetup.exe`。构建时会用 `--check` 检查安装包内置文件。更新安装包前，从托盘退出正在运行的双拼互联。自定义词库及配置在 `%APPDATA%\Rime` 或小狼毫设置的目录，安装覆盖前的副本在 `%LOCALAPPDATA%\ShuangpinLink\configuration-backup`。

Android 使用 Python 3.10+、Git、JDK 25，以及 SDK `platforms;android-37.0` 和 `build-tools;37.0.0`。准备完成后用 Gradle Wrapper 构建。`BUILD_ABI` 默认为同文的上游设置，构建本项目时设为 `arm64-v8a,x86_64`。

```sh
python -B scripts/prepare.py android
cd .build/trime
BUILD_ABI=arm64-v8a,x86_64 ./gradlew --no-daemon :app:assembleRelease
```

Windows 上请把仓库检出到纯英文路径，使用 `gradlew.bat`，并通过 `$env:BUILD_ABI` 设置架构。Android Gradle 插件会拒绝当前 `输入法` 这类含中文的构建路径。输出位于 `.build/trime/app/build/outputs/apk/release/`。GitHub Actions 提供同样的未签名构建。使用 `scripts/sign-android.ps1` 和保存在仓库之外的专用密钥完成对齐、签名及校验。APK 升级需延用相同包名和签名证书。Android 手机通常使用 `arm64-v8a`，`x86_64` 用于相应设备或模拟器。

```powershell
pwsh -NoProfile -File scripts/sign-android.ps1 `
  -UnsignedApk path-to-unsigned.apk -OutputApk dist/android/ShuangpinLink-arm64.apk `
  -BuildTools path-to-android-sdk/build-tools/37.0.0 -Keystore path-to-private-keystore.p12
```

签名前，将密钥库密码放入当前终端的 `SHUANGPIN_SIGNING_PASSWORD` 环境变量。备份密钥库并保存密码，以后用同一个证书发布更新。

## 发布两端更新

1. 在 `updates/version.json` 提高 `versionCode` 并填写新的 `versionName`。两端以 `versionCode` 判断是否有更新。重新构建 Windows 安装包和两种 APK，继续用已有 Android 证书签名。
2. 本机用更新签名密钥生成发布目录。发布脚本使用 Python、PowerShell、OpenSSL 和 Android 构建工具检查安装包版本。`.local/update-signing-key.pem` 要与 `updates/public-key.spki.b64` 对应。后续发布应保管并沿用同一密钥。

```powershell
python -B scripts/release-update.py stage `
  --key .local/update-signing-key.pem `
  --windows dist/windows/ShuangpinLinkSetup.exe `
  --arm64 dist/android/ShuangpinLink-Android-arm64-v8a.apk `
  --x86-64 dist/android/ShuangpinLink-Android-x86_64.apk `
  --aapt path-to-android-sdk/build-tools/37.0.0/aapt.exe `
  --output .build/update-release
```

3. 将发布目录、`scripts/release-update.py` 和公钥文件复制到 Ubuntu，执行以下命令。更新签名密钥和 Android 密钥留在本机。

```sh
sudo python3 -B release-update.py publish \
  --source update-release --public-key public-key.spki.b64 \
  --target /opt/shuangpin-link/updates
```

发布脚本先验证签名和三个安装包，再原子切换当前版本。上传中断后可以重新发布相同的文件。已发布版本要修正时，使用更高的 `versionCode`。发布后无需重启服务。更新接口只能由已配对的设备读取。

## 服务管理

Ubuntu 端用系统 Python 3 和 SQLite，监听 `127.0.0.1:18765`。Caddy 把 `/ime-sync/` 转发到该端口。通过 HTTPS 的公共健康检查是 `/ime-sync/health`。正常返回 `{"status":"ok","protocol":1}`。

```sh
systemctl status shuangpin-link --no-pager
sudo journalctl -u shuangpin-link -n 40 --no-pager
curl -fsS http://127.0.0.1:18765/health
```

数据库在 `/var/lib/shuangpin-link/relay.sqlite`，包含两台设备的凭据散列、邀请过期时间、密文词库和最近一条密文剪贴板。备份时使用 SQLite 一致性备份，或停止服务后备份。迁移服务器时同时保留 `/etc/shuangpin-link/setup.sha256`，并核对两端服务器地址和 TLS 证书。如果电脑端设备状态丢失，可使用启用码恢复。恢复将解除手机配对并清理旧的远端同步数据。

初始化时生成 32 字节随机启用码，采用不带 `=` 的 Base64 URL 编码。服务器只需要该字符串的 SHA-256 十六进制散列。以 root 身份执行 `scripts/deploy-ubuntu.sh /path/to/server /path/to/Caddyfile example.com /path/to/caddy caddy.service signal`，并从标准输入提供散列。最后一个参数 `signal` 适用于按配置文件启动的 Caddy 2.11+，另可选 `systemd`（已有重载命令）或 `restart`（需在维护时间执行）。脚本在重载前验证配置，健康检查失败时恢复原配置。

## 排查顺序

| 现象 | 检查 |
| --- | --- |
| Android 找不到输入法 | 先安装匹配架构的 APK，在系统设置启用并设为默认键盘，再打开一个普通输入框。 |
| 输入法显示其他拼音方案 | 确认已安装双拼互联的 Rime 配置，重新部署并选择微软双拼。若此前用过小狼毫，检查是否在另一个配置目录。 |
| 无法扫码或配对 | 检查手机相机权限、设备时间和 HTTPS 证书。关闭旧二维码后重新生成。若提示已有设备，先在电脑端解除配对。 |
| 剪贴板只能单向同步 | 确认两端同步均已恢复，并用普通文本测试。在 Android 打开键盘后重试。带系统敏感标记的复制内容会跳过。 |
| 两端词频不同步 | 两端开启词库共享，先输入并选中几次同一词，再依次点「立即同步」。确认两端 schema 使用 `rime_ice` 词库。 |
| 清空后旧词条重新出现 | 清空只处理当前设备，并关闭该设备的词库共享。另一台设备的词库仍可用。需要两端从空白开始时，先解除配对，再分别清空本机词库，最后重新配对。Windows 的清空备份在 Rime 用户目录的 `shuangpin-link-cleared` 下。 |
| 发包后 Android 提示签名冲突 | 用上次的签名密钥签名更新。卸载清除本机应用数据前，先导出需要保留的词库。 |
| 检查更新时提示无法验证 | 核对 `updates/public-key.spki.b64` 是否与发布时的私钥对应，并用发布脚本重新验证安装包及散列。 |
| 安卓下载后无法安装 | 在系统提示中允许「双拼互联」安装应用，再确认安装。核对安装包架构和应用签名是否与现有版本一致。 |
| Windows 安装后无法切换 | 检查语言设置中是否存在小狼毫，保留系统默认安全设置。查看小狼毫部署日志，并记录当前 Windows 版本。 |

客户端的密文使用 AES-256-GCM，传输格式为 Base64 编码的 `12 字节随机 nonce + 密文 + 16 字节认证标签`，附加认证数据为 `ime-sync/v1/clip` 或 `ime-sync/v1/dictionary`。中继仅处理设备权限与数据版本。调试时使用测试文字，提交日志前去除剪贴板正文、个人词条、启用码和配对信息。

## 回归验证

运行 `python -B -m unittest discover -s tests -v`。协议测试覆盖一次性邀请、设备鉴权、剪贴板长轮询、重复事件、防回传、过期、词库版本与撤销。

每次发布，用 Windows 输入框和 Android 真机核对 `nihk` 能选到「你好」，断网可打字，中文与英文可切换，续词栏可以关闭。再按照 Windows → Android、Android → Windows 顺序验证复制，最后测试两端同时复制、暂停与恢复、Android 杀进程后重新打开键盘、丢失配对后恢复，以及个人词在另一端的候选排名。
