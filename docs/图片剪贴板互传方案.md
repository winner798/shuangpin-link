# 图片剪贴板互传

0.5.0 将单张图片作为一种可单独开启的剪贴板内容。Windows 和安卓沿用已配对的设备身份。双方都启用图片能力后才可以上传。旧客户端继续通过原有文字接口收发文本。

## 输入和粘贴

支持 JPEG、PNG、GIF 和 WebP。Windows 可读取复制的单个本机图片文件、应用声明的编码图像和截图位图。安卓读取由系统授予临时访问权的图片内容 URI。用户复制链接时按文字处理。

复制后可从设备互通设置或安卓键盘顶栏观察进度。安卓通过系统输入连接将图片交给声明支持相应 MIME 的目标应用，也可以在兼容应用中直接粘贴。Windows 提供原始编码和临时文件供目标应用粘贴，并为可解码的常见图片提供位图表示。只接受位图的应用可能显示动图的第一帧。

## 传输和隐私

- 原始编码或处理后的单张图片上限为 8 MiB。PNG 透明度、动图帧与帧时长保留。默认从 JPEG、PNG 和 WebP 重建用于显示的 EXIF 朝向，移除位置、相机和文本等附加信息；GIF 移除注释和非播放用扩展。显式选择保留原图时发送原始编码字节。
- 两个方向分别派生图片专用 AES-256-GCM 密钥。每个 256 KiB 分块使用独立随机 nonce，并认证协议、方向、事件 ID、发送时间、总字节数、块序号和总块数。配对凭据、两端开关、事件时效、接收水位和本机剪贴板变化均参与收发判断。收到全部分块并通过校验后才写入剪贴板。
- 中继的图片接口在 `/v3/image` 下。每个方向最多保留一张在途或可领取的图片，密文最多保留 10 分钟。暂停、关闭、敏感字段和锁屏下的读取遵循各平台现有剪贴板保护逻辑。用户主动保存在其他应用中的副本由该应用管理。
- 收图使用设备私有短期缓存。安卓通过临时只读 URI 提供内容。Windows 需要给支持粘贴文件的应用暴露用户目录下的临时图片。图片不会写入文字历史或自动保存到相册。

## 调试

使用合成图片和临时配对。运行 `python -B -m unittest discover -s tests -v` 可验证开关、配对、重放防护、过期、取消、中断、文字兼容和 8 MiB 上限。构建工作流的图片互操作步骤将两个真实客户端的编解码器连接到本地测试中继，双向验证原始字节、分块顺序、篡改拒收，以及移除位置后各帧像素和时长是否一致。命令见 [构建工作流](../.github/workflows/build.yml)。

实机检查时，可先在一个接受图片的普通输入框打开键盘，再在 Windows 复制一张图片。点缩略图后应在目标应用内看到图片。再把焦点切到纯文本输入框，确认得到兼容性提示。反向测试时，在安卓使用能复制图片本身的应用复制图片，在 Windows 分别粘贴到图像编辑器和支持文件的目标位置。
